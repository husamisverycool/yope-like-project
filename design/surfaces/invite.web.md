## Structure (top → bottom, one column)

The column is the viewport minus `invite.web.dimension.margin` on each side, at most
`invite.web.dimension.columnMaxWidth` wide (Partiful's mobile layout applies up to its 721-px breakpoint), centred.
The whole page background is the invite's **theme colour** (see Theme).

1. Space where Partiful has its header row: the title starts `invite.web.dimension.titleTop` below the page top.
2. **Title** — the group name, centred, auto-fitted (see Title).
3. **Cover** — the group cover at full column width, own aspect, square corners. Left out when the group has none.
4. **"Invited by {first_name}"** — event-field row (Partiful's "Hosted by" row). Left out when the inviter has no first name.
5. **Member List** — header row (label left, **View all** pill right, vertically centred on the row), then every member's
   avatar in joining order, wrapping. No count line and no "+N" disc (tenet 2). **View all** is a native disclosure that
   reveals the member rows (avatar + first name).
6. **Members-only card** (Partiful "Restricted Access"): lock glyph, title, one-line explanation, large filled
   **Get the app** button at full card width.
7. **Footer**: divider, then **Get the app ↗** link, centred.

No header (logo, Login), acquisition banner, date/time, location, description, Activity list or bottom navigation:
see Do-not-copy and Gaps.

### Title

Partiful's own rule (JS [A], server branch, mobile flag): estimated width = size × (0.9 × wide + 0.7 × normal + 0.4 × thin
characters) (`invite.web.layout.title.fit`). If the whole title is wider than the column at 40 pt, the largest integer size
below 40 that wraps to ≤ 3 lines is used, else the largest below 48 that fits on one line; never below 25; then shrunk
until the widest word fits. It reproduces the captured sizes (39 px for all three reference titles at 358 px). The page
emits the result for every column width as CSS container-query steps, so it holds without script.

### Theme

Partiful lets the host pick a theme; groups have none, so the theme colour is the **mean colour of the cover**
(`invite.web.layout.theme`: the colour a fully blurred fill of the cover converges to — Partiful's blurred-fill pattern
in its link preview and App Clip card). No cover → `invite.web.color.theme.default` (#111111, Partiful's default theme).
Text is black (light theme) or white (dark theme), whichever contrasts more (WCAG 2.2), at Partiful's fixed alphas.
`prefers-color-scheme` is **not** used: Partiful's page follows the invite's theme only.

## Motion

Buttons (CSS `.ptf-PM45p`): background-colour and colour transition `invite.web.duration.button.colour` (200 ms), opacity
`invite.web.duration.button.opacity` (100 ms), `invite.web.easing.button` (ease-out). Hover (devices that hover): opacity
`invite.web.opacity.button.hover`; pressed: `invite.web.opacity.button.active`. Outlined pill instead: hover fill
`invite.web.opacity.button.outlined.hover.fill`, pressed fill `invite.web.opacity.button.outlined.active.fill`, pressed border
`invite.web.opacity.button.outlined.active.border`, opacity 1. Footer link: colour transition only. The disclosure opens
without animation (native `<details>`). Reduce Motion: nothing moves (colour/opacity fades only), no substitute needed.

## Accessibility

- Semantic structure: `h1` group name; `section` + `h2` for Member List and the members-only card; avatar list
  `ul` labelled by the Member List header; `details`/`summary` for View all; links for store hand-off.
- Text alternatives: cover `invite.web.cover.alt`; member photo alt = first name; initials disc `role="img"` named by the
  first name; state glyph `role="img"` named `invite.web.state.glyphLabel`; lock and arrow glyphs are hidden from
  assistive technology.
- Focus order: View all → Get the app (card) → Get the app (footer). Focus ring: 1-pt outline in the text colour, offset
  `invite.web.dimension.focus.offset` (Partiful's focused ring; it has no :focus-visible style of its own).
- Zoom: `width=device-width, initial-scale=1` — Partiful's `maximum-scale=1` is not copied (it blocks zoom, WCAG 1.4.4).
- Contrast: every pair is computed in `design/verification/invite.web.md` (WCAG 2.2, thresholds
  `layout.global.contrast.*`). Default/dark themes pass everything. **Failures (reported, not adjusted):**
  - the outlined View all border (alpha 0.25 on light themes) is 1.7–1.8:1 against every light theme colour Partiful uses
    (needs 3:1 as a non-text boundary; the label itself passes);
  - on mid-tone themes (grey axis #303030–#8F8F8F) text pairs fail: "Invited by" at alpha 0.8 (down to 3.84:1),
    initials on the initials disc (down to 2.52:1), View all label on its fill (4.47:1). A cover whose mean colour is
    mid-tone produces such a theme.
- Dynamic type: browser text zoom scales every size (CSS px).
- Works without JavaScript; the CSP forbids all script.

## Data & actions

- `GET /i/:token` → `invite_preview(p_token)` with the **anon** key (`docs/API.md` §6.1); cover/avatar paths signed with
  the **service role** (storage `object/sign/media`, expiry `SIGNED_URL_SECONDS`, 120 s) and fetched server-side;
  images are served from this origin, so the HTML holds no storage path, user id, Supabase URL or key.
- Only `group_name`, `group_kind` (JSON only), `cover_path`, `inviter_first_name`, `members[].first_name`,
  `members[].avatar_path` are read; anything else the RPC might return is dropped (`web/src/supabase.ts parsePreview`).
- `GET /i/:token/preview.json` — the same preview for the App Clip and apps before joining (image URLs on this origin, theme).
- Joining happens in the app: `join_group(p_token)` after phone sign-in (`docs/API.md` §9.3).
- Navigation in: `https://<domain>/i/<token>` (universal link / App Link when the app is installed — iOS
  `DeepLinkParser`, Android `DeepLink.INVITE_PATH`; the page only shows when it is not).
- Navigation out: App Store / Play listing (`Get the app`); Smart App Banner / App Clip card (iOS Safari).
- Cache: valid page, images and JSON `private, max-age=60`; every other state `no-store`. A revoked invite stops
  showing within `INVITE_CACHE_SECONDS`.

## Platform notes

- iOS Safari draws the Smart App Banner (or the App Clip card with `app-clip-display=card`) from the meta tag; Chromium
  does not, so it is not in the verification screenshots.
- Android: App Links (`/.well-known/assetlinks.json`) open the installed app; otherwise this page, and Get the app → Play
  with `referrer=invite_token%3D<token>` for the Install Referrer API.
- Association files are generated at start-up from `config/app.json` (`web/src/wellKnown.ts`).
