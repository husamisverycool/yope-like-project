# API

The contract between the backend (Supabase: `backend/supabase/migrations/`) and the iOS,
Android and web clients. Everything here is enforced in the database and covered by
`backend/tests/`. If this document and the migrations disagree, the migrations win, so
report the difference.

## 1. Conventions

- **Transport.** Clients use supabase-swift / supabase-kt with the project URL and the
  anon (publishable) key. Every request after sign-in carries the user's access token.
  The apps never hold the service role key.
- **Tables** are read through PostgREST (`from("posts").select()`). Each one has row level
  security (RLS), so a query returns only the rows the caller may see; no extra filter is
  needed for safety. Filters (`eq("group_id", …)`) are for narrowing results only.
- **Writes** go through RPCs (`rpc("create_post", params)`). The only direct table
  writes are the five listed in [5.0](#50-direct-writes-allowed).
- **RPC parameters** all start with `p_` and are passed as JSON by name, so their order
  does not matter. Optional parameters may be omitted or sent as `null`.
- **Return shapes.** An RPC that returns a table row returns a JSON object with exactly
  the table's columns. `setof <table>` / `table(...)` return a JSON array. `void` returns
  HTTP 204 with an empty body (`data == nil`). `uuid` returns a JSON string.
- **Types.** `uuid` is a lowercase string. `timestamptz` is an ISO-8601 string with offset
  (e.g. `2026-10-15T13:35:09.329469+00:00`). `date` is `YYYY-MM-DD`. `time` is returned as
  `HH:MM:SS`; send `HH:MM` or `HH:MM:SS`. Time zones are IANA names (`Europe/Paris`).
- **IDs.** Generated by the server, except `media.id`, which the client generates
  (UUID v4) so it can upload files before inserting the row
  ([recipe 9.4](#94-post-a-photo)).
- **No counts.** No column, view or RPC returns a number of reactions, views, posts or
  anything else. Reactions are rows `(user_id, emoji)`. Never request
  `Prefer: count=…` and never display a total (tenet: no counts, no streaks, no "late").
  The one integer of this kind is layout metadata: `collages.page_count`, the number of
  image files of one collage, used only to build file paths and never shown
  ([5.13](#513-collages)).
- **Files** are private. Read them through short-lived signed URLs
  (`storage.from("media").createSignedURL(path, expiresIn: 3600)`), never public URLs.

## 2. Authentication and onboarding

- **Sign-in** is phone OTP only (Twilio Verify):
  `auth.signInWithOTP(phone: "+15551234567")`, then
  `auth.verifyOTP(phone:, token: "123456", type: .sms)`. Email sign-up is disabled.
  Sessions use the default JWT expiry (3600 s) with refresh tokens.
- **Profile rows** are created automatically when the auth user is created:
  `profiles` (with `display_name` = `user_metadata.display_name`, or `""`) and
  `profile_private`. To set the name, pass `data: ["display_name": "Ana Lima"]` at OTP
  sign-in, or update `profiles` afterwards ([5.0](#50-direct-writes-allowed)).
- **Age gate** (`auth.agegate`): call `confirm_age(p_birthdate)`. While the minimum age
  is not configured it fails with `age_gate_not_configured` (503). The client must treat
  that as "cannot continue" and not skip the step. The birthdate is **not stored**. If the
  user also opts in to birthday tributes, call `set_birthday` with the same date.
- **Avatar**: upload to `avatars/<uid>/<uuid>.jpg`, then update `profiles.avatar_path`.
- **Push**: after permission is granted (and on every token change) call
  `register_device`. On sign-out call `unregister_device` before `auth.signOut()`.
- **Deleting the account**: `delete_account()` and then sign out. The session stops
  working at once (every RPC returns `not_authenticated`).

## 3. Errors

RPC and table errors come back as HTTP errors with a PostgREST JSON body:

```json
{ "code": "PT403", "message": "not_group_member", "details": null, "hint": null }
```

- `message` is the stable **error code** below. Branch on it, not on HTTP status alone.
- `code` is `PT` + the HTTP status for errors raised by our RPCs. Other codes come from
  Postgres or PostgREST: `42501` = permission denied (no grant, or an RLS `WITH CHECK`
  failure), `23514` = check constraint (e.g. a path outside your folder), `23505` =
  unique violation, `22P02` = invalid input (bad uuid/enum), `PGRST…` = request errors.
- `details` sometimes carries context (e.g. which group id failed). Display nothing from
  it to users.

| Error code | HTTP | Meaning |
|---|---|---|
| `not_authenticated` | 401 | No session, or the account was deleted. |
| `not_group_member` | 403 | Caller is not a member of that group. Also returned for group ids that do not exist. |
| `not_group_admin` | 403 | Admin-only action. |
| `not_album_owner` | 403 | Only the album's creator or a group admin can delete it. |
| `post_not_eligible` | 403 | Tribute photo is neither yours nor one you are self-tagged in. |
| `under_minimum_age` | 403 | Age gate refused. |
| `premium_required` | 402 | Video posts need an active premium entitlement. |
| `post_not_found` | 404 | Post does not exist, or the caller cannot see it (not a member / block). |
| `media_not_found` | 404 | Media does not exist or is not the caller's. |
| `message_not_found` | 404 | Message does not exist, is not visible, or is not yours (`delete_message`). |
| `member_not_found` | 404 | Target user is not a member of the group. |
| `user_not_found` | 404 | No such user. |
| `invite_not_found` | 404 | Unknown invite token. |
| `recap_not_found` | 404 | Recap does not exist or the caller is not a member. |
| `album_not_found` | 404 | Album does not exist or the caller is not a member. |
| `request_not_found` | 404 | Tribute request does not exist or is not visible (you are the honoree, not a member, or blocked with the honoree). |
| `target_not_found` | 404 | `report` target is not reachable by the caller. |
| `invite_revoked` | 410 | Invite was revoked (by its creator, an admin, or because its creator left). |
| `invite_expired` | 410 | Invite is past `expires_at`. |
| `group_full` | 409 | The group already has `max_group_members` (30) members. |
| `already_posted` | 409 | This media is already posted in that group. |
| `recap_not_ready` | 409 | The recap is still being generated (`status <> 'ready'`). |
| `tribute_closed` | 409 | The tribute request is past its due time. |
| `age_gate_not_configured` | 503 | Minimum age not configured yet; the age gate fails closed. |
| `invalid_name` | 400 | Name empty or longer than 80 characters (groups, albums). |
| `invalid_kind` | 400 | Wrong kind (e.g. `photo` in `send_message`, deleting a photo message with `delete_message`). |
| `invalid_time_zone` | 400 | Not an IANA time zone name. |
| `invalid_waking_window` | 400 | Start/end must both be set (or both null), differ, and span at least `invitation_window_seconds`. |
| `invalid_path` | 400 | A storage path outside `u/<your uid>/`. |
| `invalid_caption` | 400 | Caption longer than 1000 characters. |
| `invalid_voice` | 400 | Voice path not yours, or duration missing/≤ 0, or voice levels malformed (not 100 values of 0–31) or sent without a voice note (`details` = `voice_levels`). |
| `invalid_body` | 400 | Text message empty or longer than 4000 characters. |
| `invalid_emoji` | 400 | Not an emoji (see `react`). |
| `invalid_items` | 400 | Recap/album post list has duplicates, nulls, or posts outside the group/week. |
| `invalid_text` | 400 | Recap text longer than 2000 characters. |
| `invalid_line` | 400 | Tribute line empty or longer than 280 characters. |
| `invalid_reason` | 400 | Report reason empty or longer than 1000 characters. |
| `invalid_platform`, `invalid_token` | 400 | `register_device` arguments. |
| `invalid_quiet_hours` | 400 | Start/end must both be set (or both null) and differ. |
| `invalid_birthday`, `invalid_birthdate` | 400 | Missing, in the future, or before 1900. |
| `reply_group_mismatch` | 400 | The replied-to post is in another group. |
| `cannot_target_self` | 400 | Blocking or removing yourself. |
| `no_groups` | 400 | `create_post` without any group. |
| `invalid_argument` | 400 | A required argument is null (`details` names it). |

## 5. Tables and views

"Read" says which rows a signed-in client gets back. Columns are listed in table order.
Nullable columns are marked `?`.

### 5.0 Direct writes allowed

Everything else is written by RPCs or by the service role.

| Table | Operation | Columns the client may send | Rule |
|---|---|---|---|
| `profiles` | UPDATE | `display_name`, `avatar_path` | own row; `avatar_path` must start with `avatars/<uid>/` |
| `media` | INSERT | `id`, `owner_id`, `kind`, `original_path`, `front_original_path`, `motion_path`, `width`, `height`, `front_width`, `front_height`, `duration_ms` | `owner_id` = you (defaults to you); every path under `u/<uid>/<id>/` |
| `post_tags` | INSERT / DELETE | `post_id`, `user_id` | `user_id` = you and you can see the post (the RPCs `tag_self`/`untag_self` do the same) |
| `reports` | INSERT | `reporter_id`, `target_kind`, `target_id`, `reason` | `reporter_id` = you (prefer the `report` RPC, which validates the target) |
| `devices` | DELETE | — | own rows |
| `tribute_contributions` | DELETE | — | own row, before the request's `due_at` (withdraw) |

### 5.6 `blocks`

Read: rows where you are the blocker (the blocked person never sees the row). Written by
`block_user` / `unblock_user`.

Columns: `blocker_id` uuid, `blocked_id` uuid, `created_at` timestamptz.

A block works in both directions. Each person's posts, media, messages, reactions,
tags, walls and files are hidden from the other in every shared group. Each also stops
seeing tribute requests about the other.

`target_kind`, `target_id`, `reason`, `status` (`open|reviewed|actioned|dismissed`,
service role), `created_at`.

### 5.24 Service-role-only tables

`jobs` (work queue), `ai_cost_log` (AI cost per job), `app_config` (tunables). Clients get
`42501` on any access.

### 5.25 View `public_app_config`

Read: anyone, including signed-out users. Rows `(key text, value jsonb)` for the keys
marked public: `invitation_window_seconds`, `max_group_members`, `week_start_isodow`,
`free_history_days`, `min_age_years`. `value` is a JSON number, or JSON/SQL null when not
set.

## 6. RPCs

Call with `rpc("<name>", params: [...])`. All need a signed-in user unless marked
**anon**. "Jobs" lists the work queued in the same transaction (see
[10](#10-worker-contract-service-role)).

### 6.1 Groups

#### `create_group`
```
create_group(p_name text, p_kind group_kind, p_time_zone text,
             p_cover_path text = null, p_waking_start time = null, p_waking_end time = null) → groups
```
Creates a group; the caller becomes its only member, as `admin`. `p_name` is trimmed
(1–80). `p_time_zone` is the device's IANA zone. `p_cover_path`, if given, must be an
object you uploaded under `u/<uid>/` (convention `u/<uid>/covers/<uuid>.jpg`). Waking
hours: both or neither; omit them to use the default window.
Errors: `invalid_name`, `invalid_kind`, `invalid_time_zone`, `invalid_waking_window`,
`invalid_path`.

#### `update_group`
```
update_group(p_group_id uuid, p_name text = null, p_kind group_kind = null,
             p_cover_path text = null, p_time_zone text = null) → groups
```
Admin only. `null` = unchanged; `p_cover_path = ""` removes the cover. A replaced or removed
cover object that no other group uses is deleted (worker). Changing the time
zone reschedules unfired invitations.
Errors: `not_group_member`, `not_group_admin`, `invalid_name`, `invalid_time_zone`,
`invalid_path`.

#### `create_invite`
```
create_invite(p_group_id uuid) → group_invites
```
Any member. Returns the invite with its `token` and `expires_at`. Build the link as
`https://<domain>/i/<token>`. Errors: `not_group_member`.

#### `revoke_invite`
```
revoke_invite(p_token text) → void
```
The invite's creator or a group admin. Idempotent.
Errors: `invite_not_found` (also for non-members), `not_group_admin`.

#### `invite_preview` (**anon**)
```
invite_preview(p_token text) → jsonb
```
The only thing a non-member can learn about a group before joining:
```json
{
  "group_name": "Lima family",
  "group_kind": "family",
  "cover_path": "u/9f…/covers/1c….jpg",
  "inviter_first_name": "Ana",
  "inviter_avatar_path": "avatars/9f…/a1….jpg",
  "members": [ { "first_name": "Ana", "avatar_path": "avatars/9f…/a1….jpg" },
               { "first_name": "Rui", "avatar_path": null } ]
}
```
Members are in joining order. First names are the first word of `display_name` (null if
empty). `inviter_avatar_path` is the avatar of the invite's creator while they are a member
(the same path as their entry in `members`), else null (migration 0016). Non-members cannot read the objects behind `cover_path` / `avatar_path`, so the
web invite page (service role) signs them. The App Clip and the apps (before joining)
get the same preview with signed URLs from that web endpoint. Errors:
`invite_not_found`, `invite_revoked`, `invite_expired`.

#### `join_group`
```
join_group(p_token text) → groups
```
Adds the caller as `member`. Idempotent: if you are already a member it returns the group
even when the invite has since been revoked or has expired. Race-safe cap of 30 members.
Errors: `invite_not_found`, `invite_revoked`, `invite_expired`, `group_full`.

#### `remove_member`
```
remove_member(p_group_id uuid, p_user_id uuid) → void
```
Admin only; not yourself (use `leave_group`). The removed person's photos stay in the
group. Their invites are revoked, and birthday requests about them in this group are
deleted. Errors: `not_group_member`, `not_group_admin`, `cannot_target_self`,
`member_not_found`.

#### `leave_group`
```
leave_group(p_group_id uuid) → void
```
Anyone. If the last admin leaves, the longest-standing remaining member becomes admin.
If the last member leaves, the group and **all** its content are deleted (files
included). Your photos otherwise stay in the group; delete them first if you want them
gone. Errors: `not_group_member`.

#### `set_group_muted`
```
set_group_muted(p_group_id uuid, p_muted boolean) → void
```
Your own per-group push mute. Errors: `not_group_member`.

#### `set_group_invitation_hours`
```
set_group_invitation_hours(p_group_id uuid, p_start time, p_end time) → groups
```
Admin only (see [12](#12-open-decisions)). Both `null` = back to the default window.
`p_end <= p_start` means the window wraps past midnight. The window must be at least
`invitation_window_seconds` long. Unfired invitations are rescheduled.
Errors: `not_group_member`, `not_group_admin`, `invalid_waking_window`.

#### `set_group_invitation_paused`
```
set_group_invitation_paused(p_group_id uuid, p_paused boolean) → groups
```
Admin only (see [12](#12-open-decisions)). Pausing cancels the unfired invitation.
Errors: `not_group_member`, `not_group_admin`, `invalid_argument`.

### 6.2 Photos, chat, reactions, tags

#### `create_post`
```
create_post(p_media_id uuid, p_group_ids uuid[],
            p_caption text = null, p_voice_path text = null, p_voice_duration_ms int = null,
            p_invitation_id uuid = null, p_reply_to_post_id uuid = null,
            p_voice_levels smallint[] = null) → setof posts
```
Sends your media to one or more groups: one `posts` row and one `photo` message per
group, all or nothing. Duplicate group ids are ignored.
- You must be a member of every group (`not_group_member`, `details` = the group id) and
  own the media (`media_not_found`).
- `kind = video` requires an active premium entitlement (`premium_required`). Photos and
  Live Photos never do.
- `p_voice_path` must be your upload (convention `u/<uid>/<media_id>/voice.m4a`) and
  needs `p_voice_duration_ms > 0` (`invalid_voice`). The caption and voice note go on
  every group's post.
- `p_voice_levels` (optional, needs `p_voice_path`): the note's waveform — **exactly 100
  integers, each 0–31** (Telegram's voice waveform format: 100 five-bit values,
  https://core.telegram.org/constructor/documentAttributeAudio). Clients reduce the input
  levels they sampled while recording to 100 bucket peaks and scale them to 0–31
  (design/components.md C-36). Any other count, a value outside 0–31, a null element or a
  multi-dimensional array → `invalid_voice` (`details` = `voice_levels`).
- `p_invitation_id`: the daily invitation being answered. For the post in that
  invitation's group, `in_window = true` and `invitation_id` are set if now is within
  `[fires_at, closes_at]`. Otherwise (window closed, another group, unknown id) the post
  is an ordinary post. This never fails and never labels anything "late".
- `p_reply_to_post_id`: reply to a photo with a photo. Allowed with exactly one group,
  the replied post's group (`reply_group_mismatch`, `post_not_found`).
- `already_posted` if the media is already in one of the groups.
Jobs: `media.renditions` (once per media), `push.new_post` and `widget.refresh` per
group.

#### `send_message`
```
send_message(p_group_id uuid, p_kind message_kind, p_body text = null,
             p_voice_path text = null, p_voice_duration_ms int = null,
             p_reply_to_post_id uuid = null, p_reply_to_message_id uuid = null,
             p_voice_levels smallint[] = null) → messages
```
`text`: `p_body` non-blank, ≤ 4000 (`invalid_body`). `voice`: `p_voice_path` you
uploaded (convention `u/<uid>/voice/<uuid>.m4a`) + `p_voice_duration_ms > 0`, no body
(`invalid_voice`); optional `p_voice_levels`, the waveform in the format of `create_post`
(100 integers of 0–31, else `invalid_voice`; on a `text` message → `invalid_body`).
`photo` is refused (`invalid_kind`): use `create_post`. Reply targets
must be in the same group and visible (`post_not_found`, `reply_group_mismatch`,
`message_not_found`). Errors: `not_group_member`, plus the above. Jobs:
`push.new_message`.

#### `delete_message`
```
delete_message(p_message_id uuid) → void
```
Your own text/voice message. A photo message is removed with `delete_post`
(`invalid_kind`). Errors: `message_not_found`. Members get a `message_deleted`
broadcast.

#### `react` / `unreact`
```
react(p_post_id uuid, p_emoji text) → reactions
unreact(p_post_id uuid, p_emoji text) → void
```
Any emoji: 1–32 code points, at least one non-ASCII code point, no whitespace, no
letters. Skin tones, ZWJ families, flags and keycaps are valid. A user may react to a
post with several different emoji. `react` is idempotent (returns the existing row).
`unreact` removes only your row. Errors: `post_not_found`, `invalid_emoji`. Jobs:
`push.reaction` (cancelled if you unreact before it is sent).

#### `tag_self` / `untag_self`
```
tag_self(p_post_id uuid) → post_tags
untag_self(p_post_id uuid) → void
```
"I'm in this": only ever tags the caller. Idempotent. Errors: `post_not_found`.

#### `delete_media`
```
delete_media(p_media_id uuid) → void
```
Owner only (`media_not_found`). Deletes the photo everywhere: every post (all groups),
its chat photo messages, reactions, tags, album items, recap items, tribute
contributions, and its files. Replies stay, detached (`reply_to_post_id = null`).
Collages, tributes and year stories that used it lose their images and are re-rendered
without it. Widgets are refreshed. Members get `post_deleted` broadcasts.

#### `delete_post`
```
delete_post(p_post_id uuid) → void
```
Author only (`post_not_found`). Removes the photo from **one** group with the same
cascade. When it was the photo's last post, the media and its files are deleted too.

### 6.3 Account and safety

#### `delete_account`
```
delete_account() → void
```
Deletes everything the caller owns: media (full cascade), messages, reactions, tags,
tribute contributions, tribute requests about them, memberships (with admin hand-off;
groups where they were the last member are deleted), invites they created, devices,
quiet hours, blocks (both directions), reports they filed, entitlements, profile.
Their files (`u/<uid>/`, `avatars/<uid>/`) and the auth user are deleted by the worker.
Afterwards every call returns `not_authenticated`; sign out.

#### `block_user` / `unblock_user`
```
block_user(p_user_id uuid) → void
unblock_user(p_user_id uuid) → void
```
Idempotent. Errors: `cannot_target_self`, `user_not_found` (block only).

#### `report`
```
report(p_target_kind report_target_kind, p_target_id uuid, p_reason text) → uuid
```
Reports a post or message of one of your groups, a person you share a group with (or
have a block with), or one of your groups. Returns the report id. A block does not stop
you reporting. Errors: `target_not_found`, `invalid_reason`. Jobs: `moderation.report`.

#### `register_device` / `unregister_device`
```
register_device(p_platform device_platform, p_push_token text,
                p_push_to_start_token text = null, p_widget_push_token text = null) → devices
unregister_device(p_push_token text) → void
```
Upsert by `push_token`. Registering a token that belonged to another account moves it to
the caller. Re-register whenever any of the three tokens changes, sending all three: a
`null` clears that token. Android must not send iOS-only tokens (`invalid_token`).
Errors: `invalid_platform`, `invalid_token`.

#### `set_quiet_hours`
```
set_quiet_hours(p_start time, p_end time, p_time_zone text) → notification_settings
```
Both times `null` = no quiet hours. `p_end <= p_start` wraps past midnight.
`p_time_zone` is the device's zone and is required when times are set. Errors:
`invalid_quiet_hours`, `invalid_time_zone`.

#### `set_birthday`
```
set_birthday(p_birthday date, p_opt_in boolean) → profile_private
```
Opt in with a date to receive a birthday tribute. Opting out deletes requests about you
that are not yet due. Errors: `invalid_birthday`, `invalid_argument`.

#### `confirm_age`
```
confirm_age(p_birthdate date) → profile_private
```
Errors: `age_gate_not_configured` (503, fails closed while `min_age_years` is null),
`invalid_birthdate`, `under_minimum_age`. On success, sets `age_confirmed_at` once (it
is kept on repeat calls). The birthdate is not stored.

### 6.4 Browsing and remembering

#### `wall`
```
wall(p_user_id uuid, p_before timestamptz = null, p_limit int = 50) → table(
  item_kind text,          -- 'post' | 'collage'
  post_id uuid,            -- 'post': first post of that photo in the groups you share
  media_id uuid,           -- 'post'
  collage_id uuid,         -- 'collage'
  group_ids uuid[],        -- shared groups it appears in
  created_at timestamptz)
```
A person's photos as seen by the caller: only groups you both belong to. A photo sent to
several shared groups appears once. Also returns collages in those groups that contain
one of their photos. Newest first. Page with `p_before = <last created_at>`; `p_limit`
is clamped to 1–200. Your own wall: `p_user_id` = your id. Empty for a person with a
block with you or who shares no group with you. Errors: `invalid_argument`.

#### `group_history_weeks`
```
group_history_weeks(p_group_id uuid, p_before_week date = null, p_limit int = 8)
  → table(week_start date, post_ids uuid[])
```
Weeks (group time zone, starting on `week_start_isodow`, Monday) that have posts, newest
first. `post_ids` are in chronological order. Page with `p_before_week =` the last
`week_start` (exclusive). `p_limit` is clamped to 1–52. If `free_history_days` is set
and the caller has no premium, older posts are left out. Errors: `not_group_member`.

#### `on_this_day`
```
on_this_day(p_group_id uuid, p_local_date date)
  → table(post_id uuid, media_id uuid, author_id uuid, created_at timestamptz, years_ago int)
```
Posts from the same month and day (group time zone) in earlier years, newest first. Not
limited by `free_history_days`. Errors: `not_group_member`, `invalid_argument`.

#### `update_recap`
```
update_recap(p_recap_id uuid, p_items uuid[] = null, p_text text = null) → weekly_recaps
```
Any member, once `status = 'ready'`. `p_items` is the new order: drop ids to remove, and
re-add any post of that group from that week. `null` = unchanged; `p_text = ""` clears
the text. Posts hidden from you by a block are kept, after your order. Sets `edited_by`
and `updated_at`. Errors: `recap_not_found`, `recap_not_ready`, `invalid_items`,
`invalid_text`.

#### `save_album` / `rename_album` / `delete_album`
```
save_album(p_group_id uuid, p_name text, p_post_ids uuid[]) → albums
rename_album(p_album_id uuid, p_name text) → albums
delete_album(p_album_id uuid) → void
```
`save_album`: any member; posts must be distinct visible posts of that group, kept in
the given order. `rename_album`: any member. `delete_album`: the creator or a group
admin. Errors: `not_group_member`, `invalid_name`, `invalid_items`, `album_not_found`,
`not_album_owner`.

#### `contribute_tribute`
```
contribute_tribute(p_request_id uuid, p_post_id uuid, p_line text) → tribute_contributions
```
One contribution per person per request. Calling again replaces your photo and line
until `due_at`. The photo must be from that group and either posted by you or one you
are self-tagged in. `p_line` is trimmed, 1–280 chars. Errors: `request_not_found`,
`tribute_closed`, `post_not_found`, `post_not_eligible`, `invalid_line`.

## 7. Storage

One **private** bucket, `media`: max 100 MiB per object. Allowed types: `image/jpeg`,
`image/heic`, `image/heif`, `image/png`, `image/webp`, `video/mp4`, `video/quicktime`,
`audio/mp4`, `audio/m4a`, `audio/x-m4a`, `audio/aac`, `audio/mpeg`. Always set the
`contentType` on upload.

| Path | Written by | Readable by |
|---|---|---|
| `u/<uid>/<media_id>/original.<ext>` | owner | owner; members of any group where that media is posted (minus blocks) |
| `u/<uid>/<media_id>/front.jpg` | owner | same |
| `u/<uid>/<media_id>/motion.mov` | owner | same |
| `u/<uid>/<media_id>/voice.m4a` (post voice note) | owner | same |
| `u/<uid>/<media_id>/r/…` (renditions) | worker | same |
| `u/<uid>/voice/<uuid>.m4a` (chat voice) | owner | members of the message's group (minus blocks), once the message exists |
| `u/<uid>/covers/<uuid>.jpg` (group cover) | owner | members of any group using it as `cover_path` |
| `avatars/<uid>/<uuid>.jpg` | owner (and owner may delete) | the user and everyone sharing a group with them |
| `g/<group_id>/collages/<collage_id>/<version>/…` (files: [5.13](#513-collages)) | worker | members |
| `g/<group_id>/tributes/<tribute_id>/…` | worker | members except the honoree, who can read once the tribute is delivered |
| `g/<group_id>/year/<year>/…`, `g/<group_id>/recaps/…` | worker | members |

Rules:
- Clients may only **insert** under `u/<own uid>/` and `avatars/<own uid>/`. There is no
  overwrite (upsert fails): upload a new name instead. Clients may delete only their own
  avatars. Every other deletion is done by the worker after `delete_media`,
  `delete_post`, `delete_account` or group deletion.
- Paths: letters, digits, `_ . / -`; no `..`, no empty segments.
- Reading: `createSignedURL(path, expiresIn:)`. Use 1 h for the app and widgets. The
  notification service extension downloads the widget rendition with a signed URL it
  creates using the user's session.
- Which image to show: `display_path` (full screen), `thumb_path` (grids), `widget_path`
  (widgets), once `media.renditions_ready_at` is set. Until then, use the original.
- Listing a folder returns only the objects you can read.

## 8. Realtime

### 8.1 Postgres changes (inserts and updates)

Published tables: `messages`, `posts`, `reactions`. **Inserts and updates only.** Each
event is checked against the subscriber's RLS, so you only get rows you could select
(your groups, minus blocks). Subscribe per open group:

```swift
let ch = supabase.channel("group-\(groupId)")
let messages = ch.postgresChange(InsertAction.self, schema: "public", table: "messages", filter: .eq("group_id", value: groupId))
let posts = ch.postgresChange(InsertAction.self, schema: "public", table: "posts", filter: .eq("group_id", value: groupId))
let reactions = ch.postgresChange(InsertAction.self, schema: "public", table: "reactions", filter: .eq("group_id", value: groupId))
await ch.subscribe()
```

`UPDATE` events happen when a reply loses its target (`reply_to_*` set to null after a
deletion).

### 8.2 Private broadcast topic `group:<group_id>` (deletions)

Join with `config: { private: true }` (supabase-swift:
`supabase.channel("group:\(groupId)") { $0.isPrivate = true }`). Only current members can
join; others get an authorization error. Clients cannot send on it. Events:

| Event | Payload | Client action |
|---|---|---|
| `post_deleted` | `{ "post_id", "media_id" }` | remove the post and its chat photo message; drop it from walls, recaps, albums |
| `message_deleted` | `{ "message_id" }` | remove the message |
| `reactions_changed` | `{ "post_id" }` | refetch that post's reactions |

Realtime does not apply RLS to DELETE events, so deletions are never published as
postgres changes. That keeps other groups' deletions from reaching anyone.

### 8.3 Reliability

Realtime is best effort. An insert whose row is deleted before Realtime processes it is
not delivered. Refetch the visible page when the app returns to the foreground or the
socket reconnects. Pushes (`push.*` jobs) wake the app and widgets.

## 9. Client recipes

### 9.1 First launch
1. Phone OTP sign-in (2).
2. `confirm_age(birthdate)`. On `age_gate_not_configured`, stop and show the error
   state. Optionally `set_birthday(birthdate, true)`.
3. Name and avatar: upload `avatars/<uid>/<uuid>.jpg`, then
   `update profiles set display_name, avatar_path where id = uid`.
4. `register_device(...)` after notification permission.

### 9.2 Create a group and invite
1. Optional cover: upload `u/<uid>/covers/<uuid>.jpg`.
2. `create_group(p_name, p_kind, p_time_zone: TimeZone.current.identifier, p_cover_path)`.
3. `create_invite(group.id)`; share `https://<domain>/i/<token>`.

### 9.3 Join from a link
1. Before sign-in: show `invite_preview(token)` (anon). Signed image URLs come from the
   web endpoint.
2. After sign-in and onboarding: `join_group(token)`. Handle `group_full`,
   `invite_expired`, `invite_revoked`.

### 9.4 Post a photo
1. `let mediaId = UUID()`. Upload the original to `u/<uid>/<mediaId>/original.jpg`. Also
   upload `front.jpg` (dual capture), `motion.mov` (Live Photo) and `voice.m4a` (voice
   note) when present.
2. `insert into media { id: mediaId, kind, original_path, front_original_path?, motion_path?, width, height, front_width?, front_height?, duration_ms? }`.
3. `create_post(p_media_id: mediaId, p_group_ids: [...], p_caption?, p_voice_path?, p_voice_duration_ms?, p_voice_levels?, p_invitation_id?)`.
4. If step 3 fails, the files and media row stay private to you. Retry, or leave them.

### 9.5 Daily invitation
The push (and the iOS Live Activity / Android ongoing notification) carries the
`invitation_id`. Capture, then call `create_post` with `p_invitation_id`. The post is
`in_window` only if it arrives before `closes_at`; later it is an ordinary post. Show no
"late" state. The collage appears in `collages` (`invitation_id`) when `status = 'ready'`.

### 9.6 Group screen
Posts and chat from tables (5.8, 5.9), realtime (8), walls via `wall`, the week via
`group_history_weeks` + `weekly_recaps`, memories via `on_this_day`, albums from
`albums` / `album_items`.

### 9.7 Settings
Mute: `set_group_muted`. Quiet hours: `set_quiet_hours`. Invitation hours / pause:
`set_group_invitation_hours` / `set_group_invitation_paused` (admins). Members list:
`group_members` + `profiles`. Remove: `remove_member` (admins). Leave: `leave_group`.
Blocked people: `blocks` (+ `profiles` when you still share a group), `unblock_user`.
Delete account: `delete_account`.

## 10. Worker contract (service role)

The worker uses the service role key. It claims jobs with `claim_jobs`, finishes each
one with `complete_job` or `fail_job`, and calls the scheduler helpers on a timer. A job
whose target no longer exists must be completed as a no-op.

| RPC | Purpose |
|---|---|
| `claim_jobs(p_worker_id text, p_kinds text[] = null, p_limit int = 10) → setof jobs` | Claims due jobs (`FOR UPDATE SKIP LOCKED`); `attempts` +1. Jobs `running` longer than `job_lock_timeout_seconds` are re-claimed (or failed if out of attempts). |
| `complete_job(p_job_id bigint, p_worker_id text) → boolean` | false if the job is no longer locked by this worker. |
| `fail_job(p_job_id bigint, p_worker_id text, p_error text, p_retry boolean = true) → jobs` | Requeue at `now + min(max, base·2^(attempts−1))` (30 s, 60 s, … ≤ 1 h), or `failed` when out of attempts or `p_retry = false`. If a newer queued duplicate (same dedupe key) exists it becomes `cancelled`. Error `job_not_found`. |
| `enqueue_job(p_kind text, p_payload jsonb = {}, p_run_at timestamptz = null, p_max_attempts int = 5, p_dedupe_key text = null) → bigint` | Same-key queued jobs are merged. Errors `invalid_kind`, `invalid_argument`. |
| `schedule_daily_invitations(p_for_utc_date date) → table(group_id, local_date, invitation_id, fires_at, closes_at, created, skipped_reason)` | Call hourly for today and tomorrow (UTC). Treats the date as each group's local date. `fires_at` is a deterministic instant (seeded by md5(group, date)) inside the waking window, DST-safe, with `closes_at` inside it too. Idempotent. Skips paused/empty groups; reports `waking_window_not_set`, `window_too_short`, `window_passed`. Enqueues `invitation.fire` (run_at = fires_at) and `collage.compose` (run_at = closes_at). Error `config_missing`. |
| `due_weekly_recaps(p_now timestamptz = now()) → setof weekly_recaps` | Call every few minutes. Creates the recap of the week that ended by the latest recap moment for groups that posted that week. The recap moment is `weekly_recap_isodow` (Sunday) at the **end of the group's waking window** (its own hours, else `default_waking_end`; a window that wraps past midnight ends early on Monday): the last waking moment of its week, group-local and DST-safe. `weekly_recap_local_time`, when set, overrides that time for every group. A group with no known window and no override gets no recap. Enqueues `recap.generate`. Returns only rows it created. |
| `due_birthday_requests(p_now) → setof tribute_requests` | Creates requests `birthday_request_lead_days` (7) before an opted-in member's birthday (group-local; Feb 29 → Feb 28 in common years), in groups with another member. Enqueues `push.birthday_request`. |
| `due_tributes(p_now) → setof tributes` | Closes due requests; creates a tribute (+ `tribute.render`) only if someone contributed. |
| `due_year_stories(p_now) → setof year_stories` | From `year_story_release_month_day` (12-01) local, once per group that posted that year. Enqueues `year.compute`. |
| `release_job(p_job_id bigint, p_worker_id text) → boolean` | A stopping worker hands a running job back: `queued`, runnable now, the attempt not counted (or `cancelled` if a newer queued duplicate exists). false if not locked by this worker. |
| `apply_revenuecat_event(p_event_id text, p_user_id uuid, p_event_type text, p_event_at timestamptz, p_expires_at timestamptz, p_change boolean = true) → text` | RevenueCat webhook (worker `POST /webhooks/revenuecat`): upserts the `premium` entitlement once per event id; an event older than the newest applied one for that user is recorded but not applied. Returns `applied`, `duplicate`, `stale` or `ignored`. |

## 12. Open decisions

The owner needs to decide these. Each one is implemented with the current behaviour
described here and is easy to change.

1. **Who may change a group's invitation hours / pause invitations**
   (`set_group_invitation_hours`, `set_group_invitation_paused`). The product spec says
   "Groups can change…". Implemented: **admins only**. Alternative: any member.
2. **Who may rename the group, change its cover, kind or time zone** (`update_group`).
   Implemented: admins only.
3. **Albums**: any member can rename; only the creator or an admin can delete.
4. **`free_history_days`**: NULL = unlimited history for everyone (premium decision pending).
5. **Invite link lifetime**: `invite_ttl_seconds` = 7 days.
6. **Age gate values**: `min_age_years` is NULL (from platform research / App Store
   rating). Until it is set, nobody can pass `confirm_age`. The server does **not**
   require `age_confirmed_at` for other RPCs. Decide whether `create_group` /
   `join_group` / `create_post` should require it.
7. **Default waking window** (`default_waking_*` = 09:48–21:12, the only observed BeReal
   sample; BeReal publishes no hours) and **weekly recap time**: recaps are assembled at the
   end of each group's waking window on Sunday, the last waking moment of its week. The
   owner may set an explicit time (`weekly_recap_local_time`) or change the default window.
8. **Week start** (`week_start_isodow` = Monday) and recap day (Sunday), pending research.
9. **Year story release day**: December 1 (`year_story_release_month_day`).
10. **Tribute delivery time**: requests close at 00:00 group-local on the birthday, and
    the worker delivers as soon as the video is rendered (subject to quiet hours). The
    owner may prefer a later hour of the day.
11. **Leaving or being removed keeps your photos in the group.** Alternative: remove the
    leaver's posts from that group.
12. **`group_members.muted` is visible to co-members.** If muting should be private,
    move it to an own-rows table.
13. **Composited media and blocks**: collages, tribute videos and year stories are
    rendered once per group, so a blocked person's photo can appear in them. Recaps and
    albums are lists of post ids and are filtered per viewer.
14. **Contributors don't see each other's tribute contributions** (tenet: invitations,
    never obligations). Alternative: show contributors to other contributors.
15. **One in-window post per person per invitation** is not enforced. The collage worker
    decides how to treat several.
16. **Feb 29**: birthdays fall on Feb 28 in common years. `on_this_day` only matches
    Feb 29 posts on Feb 29.
17. **Group covers** are stored under the uploader's prefix (`u/<uid>/covers/…`). The
    group id does not exist before `create_group`, so a cover cannot go under
    `g/<group_id>/`. If the uploader deletes their account, the cover is removed.
18. **Text length limits** (name 80, caption 1000, message 4000, recap 2000, tribute line
    280, report 1000) are integrity bounds only. UI limits come from the design.
19. **Reports**: there is no moderation tooling yet. `moderation.report` jobs need a
    destination (email, dashboard).

## 13. Known limitations

- PostgREST still honours `Prefer: count=exact` (a `Content-Range` total) on any
  table. For reactions this equals the number of rows the client already receives. The
  apps must never request or display it.
- `invite_preview` returns storage paths, and paths contain their owner's user id
  (`avatars/<uid>/…`). That id is opaque and grants nothing on its own.
- Phone OTP cannot be exercised locally without Twilio credentials. The tests create
  users with the admin API and sign their own JWTs with the local secret.

## 13. Observed behaviour (verified by the iOS data-layer integration tests, 2026-10-15)

Where this section and an earlier one differ, this section describes what the database actually does.

1. **Signed-out RPC calls**: RPCs are granted only to `authenticated`; an anonymous call fails with
   Postgres `42501 permission denied for function …`, not `not_authenticated`. Clients map `42501` on
   an RPC to "not authenticated".
2. **`untag_self`** never raises `post_not_found`; untagging a post you aren't tagged in is a no-op.
3. **`save_album`** with an empty `post_ids` list raises `invalid_items`.
4. **`create_post`** stores an empty caption as NULL.
5. **`set_quiet_hours(null, null)`** keeps the row with null times; null start/end means "no quiet hours".
6. Direct table writes by clients: six tables, as listed in §5.0 (§1's "five" is out of date).
7. **`collages.page_count`** (migration 0015) is the last physical column; page files are
   `display-<n>.jpg`, `share-<n>.jpg`, `master-<n>.png` for n = 1…page_count, plus `widget.jpg`.
8. **Storage**: the resumable (TUS) upload endpoint works under the same policies (hosted projects
   require 6 MiB chunks); a duplicate upload answers HTTP 400 with body status `"409"`; an
   unreadable object answers 400 with `"404 Object not found"`.
9. **Private `group:<id>` topic**: a non-member's join is refused server-side, but supabase-swift
   2.55.4 surfaces no error — the join times out. Clients treat a join timeout as "not subscribed".
10. **Service-role helpers not listed in §10**: `release_job` (migration 0013: a job released on worker
    shutdown returns to the queue without using an attempt) and `apply_revenuecat_event` with
    `private.revenuecat_events` (0012: idempotent per RevenueCat event id).
11. **`due_year_stories`** can raise `config_invalid` (PT503) when its config key is malformed.
12. **Storage errors** are HTTP 400 with the real status in the JSON body
    (`{"statusCode":"409","error":"Duplicate",…}`), not PostgREST error bodies.
13. **Motion clips**: iOS Live Photos store `motion.mov`; Android motion clips are MP4 and are stored as
    `motion.mp4` (`video/mp4`). Storage policies only require the `u/<uid>/<media_id>/` prefix.
14. **Config defaults** (migrations 0012 and 0014 supersede §11 / §12.7): `default_waking_start` '09:48',
    `default_waking_end` '21:12', `collage_option` 'B'; weekly recaps run at the end of each group's waking
    window on the recap day when `weekly_recap_local_time` is NULL.

## 14. Selfie reactions, plans, overnight photos, weekly question (migrations 0018–0021)

Evidence and surfaces: `design/research/selfie-reactions.md`, `plans.md` + `plans-data.md`,
`overnight-and-questions.md` + `-data.md`; `design/surfaces/viewer.selfiereaction.md`, `plans.create.md`, `plans.page.md`,
`widget.countdown.md`, `camera.overnight.md`, `question.weekly.md`. Tenets hold throughout: no counts, no names of who
has not answered, one push per event, nothing asked of anyone.

### 14.1 Selfie reactions (BeReal's RealMoji)

`selfie_reactions(id, post_id, user_id, group_id, image_path, created_at)`, one per person per post. Read: members who
can see the post, blocks hide both ways (as `reactions`). Realtime: inserts and updates published; removals arrive as the
`reactions_changed` broadcast.

| RPC | Does | Errors |
|---|---|---|
| `react_with_selfie(p_post_id, p_image_path)` | upload the selfie first to `u/<uid>/selfies/<uuid>.jpg`; a new selfie replaces yours (the old file is deleted). The post's author is told once per person (`push.selfie_reaction`, type `reaction`) | `post_not_found` 404, `invalid_image` 400 (not your upload), `own_post` 400 |
| `remove_selfie_reaction(p_post_id, p_user_id = null)` | removes yours; the post's author may remove anyone's on their post | `post_not_found` 404, `not_allowed` 403 |
| `report('selfie', <selfie_reactions.id>, reason)` | report someone else's selfie | `target_not_found` 404 |

Storage: a selfie image is readable by whoever can read its row.

### 14.2 Plans (Partiful, Apple Invites)

`plans(id, group_id, created_by?, title, starts_at, ends_at?, all_day, local_date, place?, note?, cover_path?, canceled_at?,
canceled_by?, created_at, updated_at)` — `local_date` is the plan's day in the group time zone; an all-day plan starts at
00:00 of it. No delete (a cancelled plan stays and can be restored); a deleted account leaves its plans (`created_by`
null, its cover cleared). `plan_answers(plan_id, user_id, group_id, answer, answered_at)`, answer `going` / `maybe` /
`cant_go`; no answer = no row. Read: members; **Can't go rows only for their author and the plan's maker**. Realtime:
inserts and updates of both tables.

| RPC | Who | Does | Errors |
|---|---|---|---|
| `create_plan(p_group_id, p_title, p_starts_at, p_all_day=false, p_ends_at?, p_place?, p_note?, p_cover_path?)` | member | the maker answers Going; members told (`push.plan_created`); reminder queued 24 h before (skipped under 24 h) | `not_group_member` 403, `invalid_name`, `invalid_date` (before today, end before start), `invalid_place` (> 200), `invalid_note` (> 2048), `invalid_cover` 400 |
| `update_plan(p_plan_id, …same…)` | maker or admin, until the plan is over | a change of day, time or place tells Going + Maybe once (`push.plan_changed`); the reminder moves | `plan_not_found` 404, `not_allowed` 403, `plan_canceled`, `plan_past` 409 |
| `cancel_plan(p_plan_id)` / `restore_plan(p_plan_id)` | maker or admin, until over | cancel tells Going + Maybe (`push.plan_canceled`) and drops the reminder; restore tells nobody and re-queues it | same |
| `answer_plan(p_plan_id, p_answer)` / `clear_answer(p_plan_id)` | member, until over, not cancelled | one tap; replaces the previous answer | `plan_not_found` 404, `invalid_answer` 400, `plan_canceled`, `plan_past` 409 |
| `plan_photos(p_plan_id)` | member | the group's posts of the plan's local days (minus blocked authors); none for a cancelled plan | `plan_not_found` 404 |
| `next_plans(p_group_id = null)` | member | upcoming plans (not cancelled, not over) of your groups, soonest first, with `my_answer` — the group screen row and the countdown widget | `not_group_member` 403 |

"Over" = after `ends_at`, or after the end of `local_date` when there is no end (Partiful: no RSVP changes after the
event). Push type `plan` with `plan_id` (apps: `PushType.plan` / `PushTypes.PLAN`); a plan's alerts share the collapse
key `plan:<id>`.

### 14.3 Overnight photos (Dispo, Lapse)

`create_overnight_post(p_media_id, p_group_ids) → (group_id, develops_at)`: photos only (`develop_photo_only`), your own
media, your groups, once per group (`already_posted`). The photo is held in `developing_posts` (no client access) until
the first `overnight_reveal_local_time` (09:00) after it was taken, in each group's time zone. Until then **nobody** can
read it — its files are refused even to the sender. Clients only ask:

- `group_developing(p_group_id) → (developing boolean, reveal_at)` — members; no count, no names.
- `my_developing() → (developing boolean, reveal_at)` — the camera.
- `set_overnight_alerts(p_on)` — the member's switch for the reveal push (`notification_settings.overnight`, default on).

At the reveal the scheduler (`due_developed_posts`) turns each into an ordinary post (`created_at` = when taken,
`revealed_at` = the reveal time) with its chat photo message; members get one push per group and reveal time
(`push.photos_developed`, type `new_post` with the first photo's `post_id` and `revealed_at` = the reveal time, which
marks it as a reveal: Android files it under Developed Photos), the senders included, unless they muted the group or
turned overnight alerts off. Broadcast `developing_changed` (no payload) on create and reveal.

### 14.4 Weekly question (Retro prompt cards, Apple Journal)

Off unless a group admin turns it on (`set_group_weekly_question(p_group_id, p_on)`; `groups.weekly_question`, default
off) **and** `app_config.weekly_question_keys` lists the questions (copy keys `question.weekly.q*`, asked in order) —
NULL until the catalogue and its order are decided, so nothing is asked today. No push, no reminder, no streak.

- `current_group_question(p_group_id) → (id, question_key, week_start, hidden_by_me)` — this group week's question,
  created on first read; no row when off.
- `hide_question(p_question_id)` — "Remove": the card goes for you, that week.
- `answer_question(p_post_id, p_question_id | null)` — links one of your posts in that group to the question during its
  week (`invalid_question` 404, `question_off`, `question_closed` 409); null unlinks. `posts.question_id` is readable as
  any post column; nothing counts or lists who answered.

### 14.5 Unlinked upload sweep (0022)

Selfies and plan covers are uploaded before the call that links them. `due_unlinked_uploads(p_now, p_limit)`
(service role; the worker's scheduler runs it hourly) deletes such files under `u/<uid>/selfies/` and `u/<uid>/plans/`
that no row references and that are more than 7 days old. Post media, voice notes, avatars and group covers are not
swept (their uploads may wait in an app's outbox).
